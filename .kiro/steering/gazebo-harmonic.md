# Gazebo Harmonic and simulation conventions

Harmonic names only.

| Use | Never |
|---|---|
| `gz-sim-<name>-system` plugin filenames | `libgazebo_ros_*`, `gazebo_ros_*` (Classic) |
| `gz::sim::systems::<Name>` plugin classes | `ignition-gazebo-*`, `ignition::gazebo::*` (Fortress) |
| `gz.msgs.*` types in `bridge.yaml` | `ignition.msgs.*` |
| `ros_gz_sim`, `ros_gz_bridge` | `gazebo_ros_pkgs`, `ros2_control` / `gz_ros2_control` |

- Use the `ros_gz_bridge` `parameter_bridge` with `config/bridge.yaml`. Adding or changing a bridge entry is an interface change.
- Do NOT bridge DiffDrive's TF (`/model/sphere_scout/tf`). Only `ekf_node` publishes `odom -> base_link`.
- Every launch file and node sets `use_sim_time: true`.
- Every robot dimension lives in `sphere_scout_description/urdf/params.xacro`. Do not hard-code a dimension in a URDF or SDF; reference the xacro property. Missing values stay `TODO(kickoff)`.
- World values (survivor pose, heat signature, spawn) live in `apartment.sdf` and `config/ground_truth.yaml`. Don't invent them.
- The spawn pose in `gazebo_world.launch.py` is also the `odom` origin. If it changes, the localizer's `spawn_pose` and the survivor's coordinates relative to `odom` change too. Flag it.
- `apartment` meshes are generated by `tools/export_apartment.py` (Blender, Z-up). Edit the generator, not the GLBs.
- The shell joints are `left_shell_joint` and `right_shell_joint`. `/shell/cmd` is bridged to the gz topic `/shell_cmd`.
- Validate xacro and SDF before launching:
```bash
xacro src/sphere_scout_description/urdf/sphere.urdf.xacro > /tmp/robot.urdf && gz sdf -p /tmp/robot.urdf > /dev/null
gz sdf -k src/sphere_scout_gazebo/worlds/apartment.sdf
```
